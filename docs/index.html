Realistic, multi‑year retail data — from one Python command.

A configurable synthetic data generator for retail / CRM / ERP analytics. AdventureWorks-style relational schema, RetailSynth-grade cohort behavior, holiday seasonality, promotions, returns, multi-market support, and 100% reproducibility from a seed.

Get started in 30 seconds

Editable install with the optional charts extra brings in matplotlib for the visualization scripts.

Install
git clone https://github.com/scripts-and-tables/erp-synthetic-data-generator
cd erp-synthetic-data-generator
pip install -e ".[charts]"
Generate
erp-synth --seed 42 --market us --n-customers 1000 \
          --date-from 2015-01-01 --date-till 2025-12-31

python scripts/verify.py output_csv
python scripts/generate_charts.py output_csv docs/charts
Use it
import pandas as pd

lines = pd.read_csv("output_csv/sales_lines.csv")
headers = pd.read_csv("output_csv/invoice_headers.csv", parse_dates=["order_date"])

monthly = (
    lines.merge(headers[["invoice_id", "order_date", "is_return"]], on="invoice_id")
         .query("is_return == 0")
         .assign(ym=lambda d: d.order_date.dt.to_period("M"))
         .groupby("ym").line_total.sum()
)
print(monthly.tail(12))

Six axes of realism

Each design choice is grounded in established work on retail data modeling, customer-base analysis, discrete choice theory, or synthetic-data evaluation. See bibliography →

$

Realistic pricing & margins

list_price and standard_cost per SKU, line-level discounts, multi-year inflation, frozen-at-listing cost so margins drift up over time.

★

Holiday seasonality

Black Friday, Cyber Monday, Christmas, July 4 in US/EU — Ramadan, Eid al-Fitr, Eid al-Adha, UAE National Day in GCC. Each market has its own calendar.

◉

Sticky cohorts

Six behavioral segments deterministically assigned per (seed, customer_id). Same customer always gets the same cohort across runs.

%

Promotions & returns

Promotion master with anchored events, line-level discount_pct, and ~3% of orders generate a linked return invoice with negated quantities.

◆

Multi-market

--market {us,gcc,eu} swaps locale, currency, VAT, weekend definition (Sat/Sun vs Fri/Sat), payment methods, and holiday calendar.

⟲

Reproducibility

Single --seed drives every RNG (numpy + python random + Faker + pandas). Same seed → byte-identical CSVs. CI checks this on every push.

What the data looks like

All charts below are produced by scripts/generate_charts.py from the shipped 1,000-customer × 11-year sample (seed 42). Re-run on any seed to regenerate.

Holiday seasonality is built in

Nov & Dec consistently spike 2–3× above the baseline, year over year. The ramp from 2015 → 2025 reflects the logistic-growth signup curve.

Holiday calendar is real

Black Friday, Cyber Monday, Christmas Eve, July 4 — every market gets its own holiday bumps. GCC swaps in Ramadan + Eid; EU keeps Boxing Week.

Cohort retention

Six behavioral cohorts diverge cleanly on retention curves — exactly the kind of signal you'd train churn models on.

Gross margin distribution

Refills highest-margin (consumables), devices lowest (high COGS). Mean margins drift up over time because standard_cost is frozen at listing time.

Promotions show up

Discount $ given grows with the customer base. Discount-as-% of revenue clearly spikes 15–20% during Black Friday weeks vs. ~0% baseline.

Returns hold steady

Around the configured 3% rate (default --p-return 0.03). Earlier quarters noisy due to small N; converges as customer base grows.

Logistic-growth signups

Slow start → ramp → plateau, replacing the uniform-random distribution most generators ship.

Top SKUs by revenue

Premium devices and bulk industrial refills dominate. SKU-level analysis is straightforward across the 98 items in the sample.

Schema — 4 dimensions + 2 facts, fully relational

Six core CSVs plus three voice-of-customer extensions (marketing spend, support tickets, NPS). Header / line invoice split mirrors AdventureWorks' SalesOrderHeader / SalesOrderDetail.

The customer behavior model

Each customer is permanently assigned to one of six cohorts via random.Random(seed ^ customer_id). Daily buy probability is then modulated by seasonality, weekend uplift, holiday bumps, and the customer's price sensitivity.

p_buy_day = clip(
    cohort.p_buy_by_year[year_idx]            # cohort schedule
    × month_factor[month]                     # Nov 1.6, Dec 1.8, Jan 0.7, ...
    × dow_factor[dow]                         # weekend 1.15
    × holiday_bump(date)                      # Black Friday 2.5, Christmas 1.8, Eid 2.0
    × (1 - 0.20 × price_sensitivity),
    0, 1
)

So a LOYAL_HEAVY customer on Black Friday in their fourth year buys with p ≈ 31%, while the same customer on a Tuesday in February buys with p ≈ 8%. The customer also has a sticky brand_affinity that filters their product pool toward one device family.
